# プロダクト概要

選択問題に解答して学習する個人向けアプリ。科目ごとに階層化された概念・キーワードを学習対象として持ち、問題はその階層に紐づく。問題は Claude（このプロジェクトの skill）が生成・修正し、学習者は解答と品質フィードバックを通じて問題集を育てていく。

## コア機能

- **階層化された学習対象**: 科目内のキーワードを任意の深さの木で管理する。問題は葉にも途中のノードにも紐づけられる（横断的な問題）
- **SRS による出題**: 未出題の問題を優先し、次に定着率が低い順に出題する
- **判定後に学べる解答画面**: 選択と正誤を1つの選択肢内で同時に表示する。問題と各選択肢の解説、キーワードの階層を判定後に示す
- **品質フィードバックの循環**: 解答時に付けたフラグ（下記「問題フラグ」）を出力に含め、Claude による修正・新規作成のヒントにする
- **統計**: 設問ごと・キーワードごとの正答率と出題回数をヒストグラムで見る

## 想定する利用場面

括弧内の UI 優先度の規約は `tech.md` を正本とする。

- スマートフォンで出題範囲を選び、すき間時間に解く（モバイル優先）
- PC でキーワード階層や問題を整備し、条件を指定して JSON を出力し、Claude に問題の作成・修正を依頼して、結果を取り込む（PC 優先）
- 統計で弱い設問・キーワードを把握する（モバイル優先）

## 価値

- 問題作成を Claude に任せつつ、取り込み時の検証とプレビューで品質を人が管理できる
- 解答のたびに問題の品質が評価され、問題集が改善され続ける

## 問題作成の原則

この原則の正本はこの節とする。生成 skill はこれに従い、手動編集と取り込みでは同じ検証関数で確認する。

- 1問では原則として1つの情報だけを問う
  - ×「Q: XでYのものはどれ？ A: Z」→ ○「Q: Xなのはどれ？ A: Z」「Q: Yなのはどれ？ A: Z」
  - ×「Q: Xとして正しいのは？ A: YなのでZが得意」→ ○「A: Yである」「A: Zが得意」を別の問題にする
- キーワードを答える問題は原則として選択肢6個。うち2〜4個は実在する語、残りは実在しない語または学習対象外の語にする
- キーワードの特徴などを答える問題は原則として選択肢4個
- 選択肢の数は、もっともらしい誤答を作れない場合に限って減らしてよい。正解は常に1つとする
- 略語のフルネームは問題文・選択肢には書かず、解説に必ず書く
- 解説は必要な場合だけ付け、不要なら空にする（解答画面を簡潔に保つため）
  - 問題全体の解説は、選択肢の解説だけでは理解に不十分な場合に限って付ける
  - 正解の選択肢の解説は、問題文だけでは説明が不十分な場合、または選択肢に略語を含む場合に付ける
  - 誤答の選択肢には必ず解説を付ける。実在する語はその意味を短く書き、実在しない語は実在しないことを1文で書く
  - 略語を含む選択肢は、その選択肢の解説にフルネームを書く。問題文の略語は問題全体の解説に書く
- 「わからない」は固定 UI の選択肢で、データとしては持たない

## 問題フラグ

解答後に問題へ付ける品質フィードバック。名前と識別子はここを正本とし、UI・DB・交換用 JSON で共通に使う。

| 識別子 | 表示名 |
| --- | --- |
| `guessable` | 知識がなくても推測で解ける |
| `low_value` | 問う価値が低い |
| `needs_explanation` | 解説の内容を追加する |
| `defective` | 問題不備（正解・問題文の誤り、正解が一つに決まらない） |
| `comment` | 疑義の内容（自由入力） |

取り込みで修正された問題のフラグは、自動で解消済みになる（履歴としては残す）。
