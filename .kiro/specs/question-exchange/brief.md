# Brief: question-exchange

## Problem

問題は Claude が生成する。しかし、既存の学習対象・設問・品質フィードバックを Claude に渡し、生成結果を安全にアプリへ戻す経路がない。

## Current State

subject-catalog でスキーマの定義と手動編集だけができる。

## Desired Outcome

ユーザーが条件を指定して既存データを JSON で出力し、プロジェクトの skill を使って Claude に修正・新規作成用の JSON を作らせ、アプリでそれを検証・プレビューしてから取り込める。

## Approach

アプリ UI から JSON をダウンロード／アップロードする。交換フォーマットは本 spec が所有するバージョン付きの JSON スキーマとする。skill（`.claude/skills/` 配下）は出力された JSON を読み、問題作成ルールに従って取込用の JSON を書き出す。取込は単一トランザクションの RPC で行う。

## Scope

- **In**:
  - 出力条件の指定（科目、キーワードの部分木、フラグの有無・種類、正答率・出題回数などの統計条件）
  - 出力内容：キーワード階層、問題・選択肢・解説、問題フラグと疑義の自由入力、統計（ヒントとして使う）
  - 取込用フォーマット：キーワードの追加、既存問題の修正、新規問題の作成、（必要なら）問題の削除・無効化
  - 取込時の検証（スキーマ、正解が 1 つであること、選択肢の数、紐づけ先の存在）、差分プレビュー、原子的な適用
  - 取込で修正された問題のフラグの扱い（解消済みとするか等）
  - 問題生成 skill と問題作成ルール：
    - キーワードを答える問題は原則として選択肢 6 個。うち 2〜4 個は存在する単語、残りは存在しない（または学習対象に含まれない）単語にする
    - キーワードの特徴などを答える問題は原則として選択肢 4 個
    - 略語のフルネームは問題文・選択肢に書かず、解説には必ず書く
    - 1 問では原則として 1 つの情報だけを問う（例：×「XでYのものは？」→○「Xなのは？」「Yなのは？」、×「YなのでZが得意」→○「Yである」「Zが得意」を別々の問題にする）
    - 問題全体と各選択肢に解説を付ける
    - フラグ（推測で解ける、問う価値が低い、解説を追加する、問題不備、疑義）を修正・新規作成のヒントとして使う
- **Out**: アプリからの LLM API 呼び出し、出題・統計画面。

## Boundary Candidates

- 交換用 JSON スキーマ（契約）
- 出力（条件による検索）
- 取込（検証・プレビュー・適用 RPC）
- 生成 skill とルール文書

## Out of Boundary

- フラグを入力する UI（quiz-session）
- 問題の手動編集画面（subject-catalog）

## Upstream / Downstream

- **Upstream**: subject-catalog のスキーマ、quiz-session のフラグ・統計（出力に含める。quiz-session が未完成のときは、フラグ・統計を空にして出力できるようにする）
- **Downstream**: なし

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: subject-catalog、quiz-session

## Constraints

UI は PC 優先（モバイル対応あり）。大量データでも欠落なく出力する（ページング）。skill 本体はテンプレートと同様に英語で書き、生成される問題の内容は日本語にする。
