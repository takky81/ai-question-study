# Requirements Document

## Project Description (Input)

所有者は問題の生成・修正を Claude に任せたいが、既存の学習対象・設問・品質フィードバックを Claude に渡し、生成結果を安全にアプリへ戻す経路を持たない。現状は問題カタログでスキーマの定義と手動編集ができるだけである。所有者が条件を指定して既存データを JSON で出力し、プロジェクトの問題生成 skill で Claude に修正・新規作成用の JSON を作らせ、アプリでそれを検証・プレビューしてから原子的に取り込めるようにする。

## Introduction

本機能は、アプリと問題生成 skill の間の「問題の入出力」を提供する。所有者は PC（モバイル対応あり）の入出力画面で、科目・キーワードの部分木・問題フラグ・集計値の条件を指定して既存データを交換用 JSON として出力する。問題生成 skill はその JSON を読み、`product.md` の「問題作成の原則」に従って取込用 JSON を書き出す。所有者は取込用 JSON をアップロードし、検証結果と差分プレビューを確認してから、全体を一括で適用する。交換用 JSON はバージョン付きのフォーマットとし、出力・取込・skill の共通の契約とする。

### 要件定義で決めた事項

- **フラグを自動で解消する「修正」の範囲**: 取込で問題文・問題の解説・種別・選択肢（本文・解説・正解・表示順・追加・削除）・紐づくキーワードのいずれかが実際に変わった問題を「修正された問題」とする。解説だけの変更も含める（`needs_explanation` などのフラグに対する修正になるため）。取込ファイルに含まれていても内容が現在と同一の問題は修正に含めない。取込による無効化は修正に含めず、フラグを未解消のまま残す（後で有効に戻したときに、無効化の原因となった指摘を失わないため）。
- **無効化された問題の出力**: 既定では出力しない。所有者が「無効化された問題を含める」を選んだ場合に限り、状態付きで出力する。削除された問題は常に出力しない（問題カタログの定義では一覧から消え、元に戻せないため）。
- **既存問題の選択肢の削除・差し替え**: 修正する問題は選択肢の全体を記述する。既存の選択肢を識別子付きで記述すると、その選択肢を更新して識別子と解答履歴を保つ。識別子なしの選択肢は新規の選択肢として追加する。記述されなかった既存の選択肢は、問題カタログの定義どおり外された選択肢として履歴付きで残す。意味が変わる差し替えは「識別子なしの新規選択肢 ＋ 既存選択肢を記述しない」で表す（過去の解答履歴が別の意味の選択肢に付かないようにするため）。
- **出典資料からの新規作成（追加）**: 試験のシラバスなどの出典資料のテキストと対象範囲（例: 中分類）を指定し、出典の階層をキーワードの木として作り、用語ごとに問題を作る。キーワードの木は出典の階層の最下層の用語までとする（用語ごとの抜け漏れを問題0件のキーワードとして見つけ、統計画面で用語ごとの正答率を見られるようにするため）。用語例を持たない項目は、項目そのものに問題を付ける。同じ用語が複数の項目に現れる場合は項目ごとに別のキーワードとする。キーワード名に略語とフルネームが併記されている場合は略語だけを名前にする。
- **推測できる問題の検出（追加）**: 知識がなくても解ける問題を、機械的な点検と、問題ごとに独立した文脈で行う別モデルの判定の二段で検出する。判定には正解・解説・キーワードを渡さず、手がかりがあるという判定が実際の正解と一致した場合だけ推測できる問題とみなす。まとめて判定させると見落としが増えた経験があるため、1問ずつ判定する。判定は件数が多いため、費用（トークン使用量）を最小限に抑える。検出しきれないものは、解答後の問題フラグで扱う。
- **出典資料の扱い（追加）**: 出典資料（PDF とテキスト）は第三者の著作物のため、リポジトリの管理対象に含めない。問題文・解説は出典の説明文を写さず独自の文章で書く。

## Boundary Context

- **In scope**: 出力条件の指定と出力、交換用 JSON フォーマット（バージョン付き）の定義、取込ファイルの検証、差分プレビュー、原子的な適用、適用前の競合検出、取込で修正した問題のフラグの解消の呼び出し、問題生成 skill とその手順文書、出典資料からの新規作成、推測できる問題の検出（機械的な点検と問題ごとの判定）
- **Out of scope**: アプリからの LLM の呼び出し、取込画面での推測できる問題の警告表示、計算を要する問題の作成、出典資料の入手と保管、キーワードの削除（手動編集のみ）、取込による問題の削除・有効化、問題の手動編集画面、作問ルールそのものの定義、フラグの入力 UI・状態遷移、集計の計算、統計画面
- **Adjacent expectations**: 問題カタログが定義するスキーマ・作問ルールの検証・無効化と削除の意味・外された選択肢の扱いをそのまま使い、再定義しない。出題機能のフラグ・集計・定着率は参照するだけで、フラグの解消は出題機能が公開する解消処理を取込と同じ一括処理の中で呼んで行う。全件取得・認証・共通レイアウトは基盤機能のものを使う。出力・生成した JSON ファイルはソースとして扱わない

## Requirements

### Requirement 1: 出力条件の指定

**Objective:** 所有者として、修正や追加が必要な問題だけを条件で絞り込んで出力したい。それにより Claude に渡す情報を目的に合わせて小さく保てる。

#### Acceptance Criteria

1. 所有者が入出力画面の出力を開いたとき、問題入出力機能は所有者の科目一覧を表示し、出力する科目を1つ選べるようにする
2. 所有者が科目を選んだとき、問題入出力機能はその科目のキーワード階層を木として表示し、任意の深さのキーワードを範囲として選べるようにする
3. 所有者がキーワードを範囲として選んだとき、問題入出力機能は、そのキーワードと配下のすべてのキーワードのいずれかに紐づく問題を出力対象とする
4. 所有者がキーワードを選ばなかったとき、問題入出力機能は選んだ科目の問題すべてを出力対象とする
5. 所有者がフラグの条件を指定したとき、問題入出力機能は「未解消のフラグがある」「未解消のフラグがない」「指定した種類の未解消のフラグがある」のいずれかで出力対象を絞り込む
6. 所有者が統計の条件を指定したとき、問題入出力機能は正答率の範囲と出題数の範囲で出力対象を絞り込む
7. 所有者が複数の条件を指定したとき、問題入出力機能はすべての条件を満たす問題だけを出力対象とする
8. 所有者が条件を変更したとき、問題入出力機能は出力前に、条件に一致する問題数を表示する
9. 条件に一致する問題が0件の場合、問題入出力機能はその旨を表示し、キーワード階層だけを含む出力（新規作成用）を選べるようにする
10. 正答率や出題数の範囲で下限が上限を超えている場合、問題入出力機能はエラーを表示し、出力を開始しない

### Requirement 2: 出力内容

**Objective:** 所有者として、Claude が問題の修正・新規作成に必要な情報を1つのファイルで受け取れるようにしたい。それにより skill が追加の問い合わせなしに作業できる。

#### Acceptance Criteria

1. 所有者が出力を実行したとき、問題入出力機能はフォーマットのバージョン、出力日時、科目、指定した条件を含む交換用 JSON ファイルをダウンロードさせる
2. 問題入出力機能は、出力に選んだ科目のキーワード階層の全体（識別子、名前、親、兄弟の順序、階層パス）を含める
3. 問題入出力機能は、出力対象の各問題について識別子、種別、問題文、解説、紐づくキーワード、状態、最終更新日時、有効な選択肢（識別子、本文、解説、正解かどうか、表示順）を含める
4. 問題入出力機能は、出力対象の各問題の未解消のフラグ（種類、コメント、付けた日時）を含め、解消済みのフラグは含めない
5. 問題入出力機能は、出力対象の各問題の正答数・出題数・正答率・定着率と、各キーワードの部分木を含む正答数・出題数・正答率を、修正のヒントとなる参考値として含める
6. 問題入出力機能は、既定では無効化された問題を出力に含めない
7. 所有者が「無効化された問題を含める」を選んだとき、問題入出力機能は無効化された問題を、無効である状態と理由を付けて出力に含める
8. 問題入出力機能は、削除された問題と外された選択肢を出力に含めない
9. 問題入出力機能は、出力対象が1,000件を超える場合も、問題・選択肢・紐づけ・フラグ・集計値を欠落・重複なく出力する
10. 出力のためのデータ取得に失敗した場合、問題入出力機能は一部だけのファイルを作らず、失敗した操作を含む日本語のエラーと再試行の手段を表示する
11. 問題入出力機能は、出力ファイル名に科目名と出力日時を含める

### Requirement 3: 交換用 JSON フォーマット

**Objective:** 所有者として、出力・生成・取込が同じ約束事でファイルをやり取りできるようにしたい。それによりフォーマットの食い違いによる誤取込を防げる。

#### Acceptance Criteria

1. 問題入出力機能は、出力用と取込用の交換用 JSON に、フォーマットの種類（出力または取込）とバージョンを必ず持たせる
2. 問題入出力機能は、取込用 JSON で次の操作を表現できるようにする：キーワードの追加・改名・移動、既存問題の修正、新規問題の作成、既存問題の無効化
3. 問題入出力機能は、既存のキーワード・問題・選択肢を安定した識別子で参照させ、新規作成する要素を識別子なしで区別させる
4. 問題入出力機能は、同じファイル内の新規要素どうし（新規キーワードの下の新規キーワード、新規キーワードに紐づく新規問題など）を、そのファイル内だけで有効な一時キーで参照できるようにする
5. 問題入出力機能は、修正する問題に、その問題の選択肢の全体を記述させる
6. 問題入出力機能は、修正する問題の選択肢のうち、識別子付きのものを既存の選択肢の更新、識別子なしのものを新規の選択肢、記述されなかった既存の選択肢を外された選択肢（履歴として残す）として扱う
7. 問題入出力機能は、キーワードの削除、問題の削除、無効化された問題を有効に戻す操作を取込用 JSON で表現できないようにする
8. 問題入出力機能は、取込用 JSON に、取込先の科目と、もとにした出力ファイルの出力日時を記録できるようにする
9. 問題入出力機能は、フォーマットの定義（項目、型、必須・任意、意味）を、skill とアプリの両方から参照できる1つの文書として提供する

### Requirement 4: 取込ファイルの検証

**Objective:** 所有者として、取込ファイルの誤りを適用前にすべて知りたい。それにより不正なデータが一部だけ取り込まれることを防げる。

#### Acceptance Criteria

1. 所有者が取込ファイルを選んだとき、問題入出力機能はファイルを読み込み、適用せずに検証を行う
2. ファイルが JSON として読めない場合、フォーマットの種類が取込用でない場合、またはバージョンが対応外の場合、問題入出力機能はその理由を表示し、以降の検証とプレビューを行わない
3. 必須項目の欠落、型の誤り、未知の操作がある場合、問題入出力機能は該当箇所（何番目のどの要素のどの項目か）とともにエラーを表示する
4. 参照する科目・キーワード・問題・選択肢が存在しない、削除済み、所有者のものでない、または別の科目に属する場合、問題入出力機能は該当箇所とともにエラーを表示する
5. 選択肢の識別子が修正対象の問題以外のものである場合、問題入出力機能はエラーを表示する
6. キーワードの追加・移動の結果、自分自身または配下を親とする循環が生じる場合、問題入出力機能はエラーを表示する
7. キーワードの追加・改名・移動の結果、同じ親の下に同じ名前のキーワードが並ぶ場合、問題入出力機能はエラーを表示する
8. 一時キーが重複している、または定義されていない一時キーを参照している場合、問題入出力機能はエラーを表示する
9. 同じキーワード・問題がファイル内で複数の操作の対象になっている場合（同じ問題の修正と無効化など）、問題入出力機能はエラーを表示する
10. 問題入出力機能は、修正後と新規作成の各問題に、問題カタログの作問ルールの検証を適用し、エラーと警告を区別して該当箇所とともに表示する
11. 検証でエラーが1件でもある場合、問題入出力機能は適用の操作を行えないようにする
12. 削除された問題を修正・無効化の対象としている場合、問題入出力機能はエラーを表示する
13. 無効化された問題を修正の対象としている場合、問題入出力機能は修正を受け付け、問題が無効のまま残ることを警告として表示する

### Requirement 5: 差分プレビュー

**Objective:** 所有者として、適用で何が変わるかを適用前に確認したい。それにより Claude の生成結果を人が品質管理できる。

#### Acceptance Criteria

1. 検証が完了したとき、問題入出力機能は、キーワードの追加・改名・移動、問題の修正・新規作成・無効化の件数を表示する
2. 問題入出力機能は、修正される問題ごとに、変わった項目（問題文、解説、種別、紐づくキーワード、選択肢の追加・変更・削除・並べ替え・正解の変更）の変更前と変更後を並べて表示する
3. 問題入出力機能は、新規作成される問題の内容と、紐づくキーワードの階層パスを表示する
4. 問題入出力機能は、キーワードの追加・改名・移動を、変更前と変更後の階層パスで表示する
5. 問題入出力機能は、無効化される問題と無効化の理由を表示する
6. 取込ファイルに含まれていても内容が現在と同一の問題がある場合、問題入出力機能はその問題を「変更なし」として区別して表示し、適用の対象にも修正された問題にも含めない
7. 問題入出力機能は、修正された問題ごとに、適用によって解消済みになる未解消のフラグを表示する
8. 取込ファイルの出力日時より後に、プレビュー対象の問題またはキーワードが更新されている場合、問題入出力機能はその要素に「出力後に更新されています」と警告を表示する
9. 適用で変化が1件もない場合、問題入出力機能はその旨を表示し、適用の操作を行えないようにする
10. 警告がある場合、問題入出力機能は警告の一覧を表示し、所有者が警告を確認したことを示す操作をしてから適用できるようにする

### Requirement 6: 原子的な適用

**Objective:** 所有者として、確認した変更をすべてまとめて反映したい。それにより途中で失敗しても問題集が中途半端な状態にならない。

#### Acceptance Criteria

1. 所有者が適用を実行したとき、問題入出力機能はプレビューに示したすべての変更を1つの一括処理として反映する
2. 適用のいずれかの変更が失敗した場合、問題入出力機能はすべての変更を取り消し、データを適用前の状態のままにする
3. 問題入出力機能は、既存のキーワード・問題・選択肢を更新しても、その識別子を変えない
4. 問題入出力機能は、新規作成したキーワード・問題・選択肢に新しい識別子を割り当て、一時キーによる参照を新しい識別子で解決する
5. 問題入出力機能は、問題の無効化と外された選択肢を、問題カタログの定義どおり履歴を残す形で反映する
6. 適用が成功したとき、問題入出力機能は反映した件数と解消したフラグの件数を表示する
7. 適用が失敗した場合、問題入出力機能は日本語で理由を表示し、取込ファイルとプレビューを保持して再検証できるようにする
8. 適用の処理中の間、問題入出力機能は適用の操作を無効にし、二重に適用されないようにする

### Requirement 7: プレビュー後の変更の検出

**Objective:** 所有者として、プレビューを見ている間に手動編集などでデータが変わった場合は適用を止めたい。それにより確認していない状態に変更を上書きすることを防げる。

#### Acceptance Criteria

1. 問題入出力機能は、プレビューの作成時点で、変更・参照の対象となるキーワードと問題の状態を記録する
2. 適用時に、対象のキーワードまたは問題がプレビューの作成後に更新・削除されていた場合、問題入出力機能は何も反映せずに適用を中止する
3. 適用を中止したとき、問題入出力機能は、プレビュー後にデータが変更されたことと、再検証が必要であることを表示し、再検証の操作を提供する
4. 所有者が再検証を実行したとき、問題入出力機能は同じ取込ファイルを現在のデータに対して検証し直し、プレビューを作り直す

### Requirement 8: 取込で修正された問題のフラグの解消

**Objective:** 所有者として、取込で直した問題の指摘を自動で片付けたい。それにより未解消のフラグが「まだ直していない問題」だけを表すようになる。

#### Acceptance Criteria

1. 取込の適用が成功したとき、問題入出力機能は、修正された問題の未解消のフラグを、同じ一括処理の中で解消済みにする
2. 問題入出力機能は、問題文・問題の解説・種別・選択肢（本文・解説・正解・表示順・追加・削除）・紐づくキーワードのいずれかが実際に変わった問題を、修正された問題とする
3. 問題入出力機能は、内容が変わらなかった問題、新規作成した問題、取込で無効化しただけの問題のフラグを解消しない
4. 適用が失敗した場合、問題入出力機能はフラグの状態も変更しない
5. 問題入出力機能は、解消したフラグを履歴として残し、フラグを直接削除・書き換えしない

### Requirement 9: 問題生成 skill

**Objective:** 所有者として、出力した JSON を Claude に渡すだけで、作問ルールに沿った取込用 JSON を作らせたい。それにより問題の作成・修正を任せつつ品質の基準を保てる。

#### Acceptance Criteria

1. 所有者が出力 JSON のパスと依頼内容を指定して問題生成 skill を実行したとき、問題生成 skill は出力 JSON を読み、取込用 JSON をローカルのファイルとして書き出す
2. 問題生成 skill は、`product.md` の「問題作成の原則」に従って問題・選択肢・解説を作成・修正する
3. 問題生成 skill は、問題文・選択肢・解説などの生成内容を日本語で書く
4. 問題生成 skill は、出力 JSON の未解消のフラグを、フラグの種類ごとの対処方針（推測で解ける問題の誤答の見直し、価値の低い問題の無効化の検討、解説の追記、不備の訂正、コメントへの対応）に従って修正のヒントとして使う
5. 問題生成 skill は、出力 JSON の集計値を、修正・新規作成の優先度を決める参考として使い、集計値そのものを取込用 JSON に書かない
6. 問題生成 skill は、交換用 JSON フォーマットの定義に従い、既存の要素を識別子で、新規の要素を一時キーで参照する
7. 問題生成 skill は、意味が変わる選択肢の差し替えを、識別子なしの新規選択肢として書き、既存の選択肢の識別子を別の意味の選択肢に流用しない
8. 問題生成 skill は、出力 JSON がフォーマットの種類・バージョンの点で対応外の場合、取込用 JSON を書かずに理由を報告する
9. 問題生成 skill は、書き出しの前に作問ルール（正解が1つ、選択肢の数、略語のフルネームが解説にあること、問題と各選択肢に解説があること）を自己点検し、作業の最後に、修正・新規作成・無効化の件数と、原則から外れる判断をした箇所を報告する
10. 問題生成 skill は、データベースや認証情報に触れず、アプリへの取込を所有者の操作に任せる

### Requirement 10: 入出力画面の導線と操作性

**Objective:** 所有者として、PC で出力と取込を迷わず行い、必要ならモバイルでも操作したい。それにより問題集の整備を一続きの作業として進められる。

#### Acceptance Criteria

1. 問題入出力機能は、管理の区分に入出力の導線を表示し、ログインした所有者だけが利用できるようにする
2. 問題入出力機能は、PC 幅で出力条件とプレビューの差分を読みやすく並べて表示する
3. モバイル幅で表示している間、問題入出力機能は出力・取込・プレビューを横スクロールなしで操作できるようにする
4. 問題入出力機能は、キーボードだけで条件指定・ファイル選択・確認・適用を行えるようにし、操作要素に 44px 相当の操作領域とフォーカス表示を持たせる
5. 問題入出力機能は、プレビューの選択肢の正解を、アプリ共通の正解の色と印で示す
6. 問題入出力機能は、取込ファイルとプレビューを保持している間に画面を離れようとしたとき、破棄してよいかを確認する
7. 問題入出力機能は、所有者以外のデータを出力に含めず、所有者以外のデータを取込で変更しない

### Requirement 11: 出典資料からの新規作成

**Objective:** 所有者として、試験のシラバスなどの出典資料と対象範囲を指定するだけで、出典の階層に沿ったキーワードと問題を作らせたい。それにより出題範囲を漏れなく、用語単位で学習・確認できる。

#### Acceptance Criteria

1. 所有者が出力 JSON・出典資料のテキスト・対象範囲を指定して問題生成 skill を実行したとき、問題生成 skill は対象範囲の出典の階層と用語からキーワードと問題を作り、取込用 JSON を書き出す
2. 問題生成 skill は、出典の階層を上位から用語までキーワードの木として表し、出力 JSON にすでにある同じ位置のキーワードは識別子で参照して重複して作らない
3. 問題生成 skill は、問題を最下層のキーワードに紐づけ、用語例を持たない項目では項目のキーワードに紐づける
4. 同じ用語が出典の複数の項目に現れる場合、問題生成 skill は項目ごとに別のキーワードとし、問題をその項目の文脈で作る
5. 出典の用語に略語とフルネームが併記されている場合、問題生成 skill は略語だけをキーワード名にし、フルネームを解説に書く
6. 問題生成 skill は、出典の説明文を写さず、問題文・選択肢・解説を独自の文章で書く
7. 問題生成 skill は、用語ごとに少なくとも1問を作る（用語ではない語は 11.9 と 11.10 に従う）。その1問は用語そのものを正解とする問題に限らず、用語の特徴を問う問題や、その用語の知識がないと解けない別の語を正解とする問題でもよい
8. 問題生成 skill は、1つの取込用 JSON に含める範囲を出典の中分類1つまでとし、それを超える指定は分割を求めて報告する
9. 出典の用語例の語が用語ではない場合（「その他のソート」のような分類の総称や、「サーバーへの利用集中」のような事象・状況の説明）、問題生成 skill はその語を正解とする問題を作らない
10. 用語ではない語が学習の価値がある内容を表す場合、問題生成 skill はその語をキーワードとし、その内容（原因・対策・具体例など）を問う問題を作る。価値がない場合はキーワードも問題も作らずに報告する
11. 問題生成 skill は、作業の最後に、対象範囲の用語数、作成したキーワード数と問題数、作れなかった用語と理由、用語ではないと判断した語とその扱いを報告する
12. 計算を要する用語の場合、問題生成 skill は具体的な値を求めさせず、計算方法（式の形、手順、使う値の意味）を問う問題を作る。計算方法も選択式で問えない場合に限り、作らずに理由を報告する

### Requirement 12: 推測できる問題の機械的な点検

**Objective:** 所有者として、問題文と選択肢の見た目だけで正解を絞り込める問題を、取込の前に機械的に見つけたい。それにより知識がなくても解ける問題を減らせる。

#### Acceptance Criteria

1. 問題生成 skill は、作成・修正した問題を取込用 JSON に書き出す前に、推測の点検にかける
2. 推測の点検は、正解の選択肢と問題文に共通する語句があり、誤答の選択肢には同程度の共通がない問題を警告する
3. 推測の点検は、正解の選択肢の長さだけが他の選択肢から大きく外れる問題を警告する
4. 推測の点検は、1つの選択肢だけ語尾や表記の形式が他と異なる問題を警告する
5. 推測の点検は、断定的な語（「必ず」「すべて」など）が誤答の選択肢にだけ現れる問題を警告する
6. 推測の点検は、ある選択肢の文言が別の選択肢の文言を含む問題を警告する
7. 推測の点検は、略語のフルネームが問題文または選択肢に現れる問題を警告する
8. 推測の点検は、問題ごとに警告の種類と該当する語句を示す
9. 推測の点検で警告された場合、問題生成 skill は問題を作り直して再点検するか、作り直さない理由を報告する

### Requirement 13: 推測できる問題の問題ごとの判定

**Objective:** 所有者として、機械的な点検では見つけられない推測の手がかり（語の一般的な意味など）を、1問ずつ独立に判定させたい。それにより推測で解ける問題が取り込まれるのを減らせる。

#### Acceptance Criteria

1. 問題生成 skill は、推測の点検を通った問題を、1問ずつ他の問題と文脈を共有しない判定にかける
2. 推測の判定は、問題文と選択肢だけを判定に渡し、正解・解説・キーワードを渡さない
3. 推測の判定は、選択肢の並びを問題ごとに入れ替えて判定に渡す
4. 推測の判定は、分野の知識がない受験者を想定し、見た目の手がかり（問題文との語の重なり・長さ・形式・断定語）と、一般的な意味の手がかり（語の日常的な意味だけで正解が問題文に合い、誤答が合わないと分かること）のそれぞれで絞り込める選択肢があるかを判定させる。判定するモデル自身の分野の知識で分かる選択肢は、これらの手がかりと区別して答えさせ、推測の手がかりとして数えない
5. 推測の判定は、手がかりがあるとされた選択肢が実際の正解と一致した場合だけ、その問題を推測できる問題とし、手がかりの種類を記録する
6. 推測できる問題とされた場合、問題生成 skill は誤答を、一般的な意味でも問題文に当てはまりそうな実在する語へ、それが難しい場合は正解と同じ語の部品で作った実在しない語へ差し替えて作り直し、再判定する。用語の字面がそのまま意味を表すなど誤答の差し替えで解消できない場合は、11.7 に従い問い方（特徴を問う問題、または別の語を正解とする問題）を変えて作り直す
7. 推測の判定の作り直しは1問につき5回までとし、それでも推測できる問題は作り直しをやめて報告する
8. 問題生成 skill は、実在しない語を誤答に使った場合、その選択肢の解説に実在しない語であることを書く
9. 推測の判定は、1回の判定で使う入力と出力を、問題1問と判定の指示、決まった形式の短い結果に限る
10. 問題生成 skill は、作業の最後に、判定した問題数、推測できる問題とされた問題数と手がかりの種類の内訳、作り直しても解消しなかった問題を報告する
11. 判定を実行できない場合、問題生成 skill は取込用 JSON を判定済みとして扱わず、未判定の問題を報告する

### Requirement 14: 出典資料の管理

**Objective:** 所有者として、第三者の著作物である出典資料を手元でだけ使いたい。それにより公開リポジトリに出典資料を載せずに済む。

#### Acceptance Criteria

1. 問題入出力機能は、出典資料・出力 JSON・取込用 JSON を置く作業用の場所を1か所に定め、その場所の中身を種類によらずすべてリポジトリの管理対象から外す
2. 問題生成 skill は、出典資料をテキストとして読み、出典資料そのものを取込用 JSON や手順文書に書き写さない
