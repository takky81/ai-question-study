# Requirements Document

## Project Description (Input)

学習対象（科目内で階層化された概念・キーワード）と、それに紐づく選択問題を保持・閲覧・編集する仕組みがない。現状はアプリの基盤（認証、共通レイアウト、テーマ、ページング）だけがある。所有者本人が PC 上で科目を作成し、キーワード階層と問題（問題文、選択肢、正解、問題と各選択肢の解説、紐づくキーワード）を一覧・検索・編集できるようにし、出題・取込・統計の各機能が利用する安定したデータ定義を確定する。

## Introduction

本機能は、所有者が科目ごとにキーワードの階層（任意の深さの木）と選択問題を管理する「問題カタログ」を提供する。問題は階層の葉にも途中のノードにも紐づけられる。問題作成の原則（`product.md` の「問題作成の原則」）に基づく検証を手動編集で行い、同じ検証を取込機能からも使えるようにする。問題・選択肢・キーワードは移動・改名しても変わらない安定した識別子を持つ。

## Boundary Context

- **In scope**: 科目の作成・改名・削除、キーワード階層の作成・改名・削除・並べ替え・移動、問題（種別、問題文、選択肢、正解、解説、紐づくキーワード）の一覧・絞り込み・作成・編集・無効化・削除、問題作成ルールの検証、キーワードの階層パスと配下の取得、管理画面
- **Out of scope**: 出題、解答履歴、SRS 状態、問題フラグ、JSON の出力と取込、統計画面。「わからない」選択肢はデータとして持たない
- **Adjacent expectations**: 出題機能は無効化・削除された問題を出題せず、集計からも除外する（本機能は問題の状態を公開する）。取込機能は本機能と同じデータ定義と検証規則を使い、安定した識別子で既存要素の更新と新規作成を区別する。認証・共通レイアウト・テーマ・全件取得は基盤機能が提供するものを使う

## Requirements

### Requirement 1: データの所有と安定した識別子

**Objective:** 所有者として、自分のカタログが自分だけに見え、要素の識別子が変わらないようにしたい。それにより他の機能や取込で同じ要素を確実に参照できる。

#### Acceptance Criteria

1. 問題カタログは、科目・キーワード・問題・選択肢を、それを作成した所有者だけが閲覧・変更できるようにする
2. 所有者以外の利用者がカタログの要素を閲覧または変更しようとした場合、問題カタログはその要素を返さず、変更を拒否する
3. 問題カタログは、科目・キーワード・問題・選択肢に、作成時に一意の識別子を割り当てる
4. キーワードを改名・移動・並べ替えたとき、または問題・選択肢を編集したとき、問題カタログはその要素の識別子を変えない

### Requirement 2: 科目の管理

**Objective:** 所有者として、学習対象を科目ごとに分けたい。それにより科目単位でキーワードと問題を整理できる。

#### Acceptance Criteria

1. 所有者が科目名を入力して作成したとき、問題カタログは科目を作成し、科目一覧に表示する
2. 所有者が科目名を変更したとき、問題カタログは新しい名前を保存して一覧に反映する
3. 空の科目名、または同じ所有者の既存科目と同じ名前が入力された場合、問題カタログは保存せず、理由を示すエラーを表示する
4. 所有者が科目の削除を求めたとき、問題カタログは配下のキーワード数と問題数を示した確認を表示する
5. 所有者が科目の削除を確定したとき、問題カタログは科目と配下のキーワードを削除し、配下の問題を削除状態にする（Requirement 6 の削除と同じ扱い）

### Requirement 3: キーワード階層の管理

**Objective:** 所有者として、科目内のキーワードを任意の深さの木で整理したい。それにより概念の包含関係に沿って問題を紐づけられる。

#### Acceptance Criteria

1. 所有者が科目の直下または既存キーワードの下にキーワード名を入力して追加したとき、問題カタログはその位置の兄弟の末尾にキーワードを作成する
2. 問題カタログは、キーワード階層を親子関係と兄弟の順序に従った木として表示し、各ノードを展開・折りたたみできるようにする
3. 所有者がキーワード名を変更したとき、問題カタログは新しい名前を保存し、そのキーワードに紐づく問題の紐づけを維持する
4. 空のキーワード名、または同じ親の下に同じ名前の兄弟が既にある名前が入力された場合、問題カタログは保存せず、理由を示すエラーを表示する
5. 所有者がキーワードの兄弟間の順序を変更したとき、問題カタログは新しい順序を保存し、再表示しても同じ順序で表示する
6. 所有者がキーワードを同じ科目内の別の親（または科目の直下）へ移動したとき、問題カタログは配下の部分木ごと移動し、移動先の兄弟の末尾に置く
7. キーワードを自分自身またはその配下へ移動しようとした場合、問題カタログは移動を拒否し、理由を示すエラーを表示する
8. 所有者がキーワードの削除を求めたとき、問題カタログは削除される部分木のキーワード数、紐づけが外れる問題数、紐づけがなくなり無効化される問題数を示した確認を表示する
9. 所有者がキーワードの削除を確定したとき、問題カタログはそのキーワードと配下の部分木を削除し、それらへの問題の紐づけを外す
10. キーワードの削除によって紐づくキーワードが1つもなくなる問題がある場合、問題カタログはその問題を削除せずに無効化し、無効化の理由として紐づけ先の喪失を記録する

### Requirement 4: 問題の作成と編集

**Objective:** 所有者として、問題文・選択肢・正解・解説・紐づくキーワードを1つの画面で編集したい。それにより問題を手作業で整備できる。

#### Acceptance Criteria

1. 問題カタログは、問題ごとに、種別（キーワードを答える問題／キーワードの特徴などを答える問題）、問題文、問題全体の解説、1つ以上の紐づくキーワード、順序付きの選択肢を保持する
2. 問題カタログは、選択肢ごとに、選択肢の本文、正解かどうか、選択肢の解説を保持する
3. 問題カタログは、問題を、同じ科目内の葉のキーワードにも途中のキーワードにも、また複数のキーワードにも紐づけられるようにする
4. 所有者が新しい問題を作成するとき、問題カタログは種別に応じた原則の選択肢数（キーワードを答える問題は6個、特徴などを答える問題は4個）の空欄を初期表示する
5. 所有者が選択肢を追加・削除・並べ替えたとき、問題カタログは編集中の問題に反映し、保存時に表示順を保存する
6. 所有者が問題を保存したとき、問題カタログは問題・選択肢・紐づけを一括で保存し、一部だけが保存された状態を残さない
7. 保存に失敗した場合、問題カタログは操作の内容を含む日本語のエラーを表示し、編集中の入力を保持して再試行できるようにする
8. 保存処理中の間、問題カタログは保存操作を受け付けず、二重保存を防ぐ
9. 問題カタログは、「わからない」の選択肢をデータとして保持せず、編集画面にも表示しない

### Requirement 5: 問題作成ルールの検証

**Objective:** 所有者として、保存前に問題が作成の原則に沿っているか確認したい。それにより品質の低い問題が混入するのを防げる。

#### Acceptance Criteria

1. 問題カタログは、問題の内容を受け取り、違反ごとに対象箇所と日本語の説明と重大度（エラーまたは警告）を返す検証規則を提供し、手動編集と取込の両方で同じ規則を使えるようにする
2. 正解の選択肢が1つでない場合、問題カタログはエラーとして報告する
3. 問題文、問題全体の解説、いずれかの選択肢の本文または解説が空の場合、問題カタログはエラーとして報告する
4. 選択肢が2個未満の場合、または同じ問題内に同じ本文の選択肢が複数ある場合、問題カタログはエラーとして報告する
5. 紐づくキーワードがない場合、または問題の科目に属さないキーワードが紐づけられている場合、問題カタログはエラーとして報告する
6. 選択肢数が種別の原則（キーワードを答える問題は6個、特徴などを答える問題は4個）より少ない場合、問題カタログは警告として報告する。原則より多い場合はエラーとして報告する
7. 問題文または選択肢に略語（英大文字2文字以上の語）が含まれ、その略語が問題全体の解説にも選択肢の解説にも現れない場合、問題カタログはフルネームを解説に書くよう警告する
8. 検証でエラーがある場合、問題カタログは問題を保存せず、該当する入力欄の近くに説明を表示する
9. 検証で警告だけがある場合、問題カタログは警告を表示し、所有者が確認したときに保存する
10. 問題カタログは、データの保存時にも、正解が1つであること、紐づけ先のキーワードが同じ科目に存在すること、キーワード階層に循環がないことを保証し、満たさない保存を拒否する

### Requirement 6: 問題の無効化と削除

**Objective:** 所有者として、不適切な問題を出題から外したり削除したりしたい。それにより学習の品質を保ちつつ、解答の記録を失わない。

#### Acceptance Criteria

1. 所有者が問題を無効化したとき、問題カタログは問題を無効状態にし、無効化の日時と任意の理由を記録する
2. 所有者が無効な問題を有効に戻したとき、問題カタログは無効化の記録を消して有効状態にする。ただし紐づくキーワードがない問題は有効に戻せず、理由を示すエラーを表示する
3. 所有者が問題の削除を確定したとき、問題カタログは問題を削除状態にし、通常の一覧・検索・編集の対象から外す
4. 問題カタログは、削除状態にした問題とその選択肢の識別子と内容を保持し、他の機能がその問題に関する過去の記録を参照できるようにする
5. 問題カタログは、無効状態または削除状態の問題を「出題対象外・集計対象外」として他の機能が判別できる状態を公開する
6. 所有者が削除を求めたとき、問題カタログは削除した問題が一覧から消え元に戻せないことを示す確認を表示する

### Requirement 7: 問題の一覧と絞り込み

**Objective:** 所有者として、多数の問題から目的の問題をすばやく見つけたい。それにより編集や見直しの対象を選びやすくなる。

#### Acceptance Criteria

1. 所有者が科目を選んだとき、問題カタログはその科目の問題を一覧表示し、各行に問題文の冒頭、種別、状態（有効／無効）、紐づくキーワード名を示す
2. 所有者がキーワードを指定したとき、問題カタログはそのキーワードとその配下のキーワードのいずれかに紐づく問題だけを表示する
3. 所有者が種別、状態、問題文・選択肢・解説に含まれる語を指定したとき、問題カタログは条件をすべて満たす問題だけを表示する
4. 問題カタログは、条件に一致する件数を表示し、1ページ50件ずつのページ送りで、件数が1,000件を超えても欠落や重複なく全件を辿れるようにする
5. 問題カタログは、一覧を作成日時の新しい順に、同時刻の問題も毎回同じ順序で表示する
6. 条件に一致する問題がない場合、問題カタログは該当なしであることを表示する
7. 一覧の取得に失敗した場合、問題カタログは日本語のエラーと再試行の操作を表示する

### Requirement 8: キーワードの階層パスと配下の取得

**Objective:** 他の機能の開発者として、キーワードの祖先込みのパスと配下の部分木を同じ規則で得たい。それにより出題・取込・統計で階層の扱いがずれない。

#### Acceptance Criteria

1. 問題カタログは、キーワードを指定すると、科目の直下から当該キーワードまでの祖先を順に並べた階層パスを返す
2. 問題カタログは、キーワードを指定すると、当該キーワードと配下のすべてのキーワードを返す
3. 存在しないキーワードが指定された場合、問題カタログは空の結果を返す
4. 問題カタログは、階層の深さや兄弟数に関わらず、配下のキーワードを欠落や重複なく返す
5. 問題カタログは、問題一覧や編集画面で、紐づくキーワードを階層パスとして表示する

### Requirement 9: 管理画面の利用性

**Objective:** 所有者として、PC で効率よく、必要ならスマートフォンでもカタログを整備したい。それによりいつでも問題集を手入れできる。

#### Acceptance Criteria

1. 問題カタログは、共通レイアウトの管理の区分に導線を表示し、ログイン済みの所有者だけが管理画面を開けるようにする
2. PC 幅で表示している間、問題カタログはキーワード階層と問題一覧を同じ画面に並べて表示する
3. モバイル幅で表示している間、問題カタログはキーワード階層と問題一覧を切り替えて表示し、横スクロールを発生させない
4. 問題カタログは、すべての操作をキーボードで行えるようにし、操作要素に 44px 相当の操作領域とフォーカス表示を持たせる
5. 問題カタログは、編集画面で正解の選択肢を正解の共通色と印で示し、警告や危険操作の色を正誤表示に使わない
6. 所有者が未保存の変更がある編集画面から離れようとしたとき、問題カタログは変更を破棄するか確認する
