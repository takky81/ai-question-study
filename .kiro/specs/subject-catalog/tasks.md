# Implementation Plan

前提: 上流の app-foundation（ルート登録表、保護ルート、共通ページング、所有者の seed アカウント、ユニット／E2E の実行基盤）が実装済みであること。

- [ ] 1. 基盤: カタログのスキーマと RPC

- [ ] 1.1 カタログのテーブル、制約、RLS、ビューの migration を作る
  - 科目・キーワード・問題・選択肢・問題とキーワードの紐づけの各テーブルを、所有者列（既定値は現在のユーザー）と作成時に割り当てる UUID 付きで定義する
  - 科目の論理削除と有効な科目内での名前の一意性、兄弟キーワード名の一意性（科目直下を含む）、空文字の禁止、種別の値の制限を設ける
  - 全テーブルで RLS を有効化し、参照と書き込みの両方を所有者本人に制限する
  - 内部用スキーマに更新日時の自動更新、キーワードの親の同一科目・循環の検査、紐づけ先の同一科目の検査、兄弟末尾への並び順の自動設定のトリガーを置き、クライアントから実行できないようにする
  - 有効な選択肢の正解を最大1つに制限する部分 unique index と、コミット時に正解がちょうど1つかを検査する遅延制約トリガーを設ける
  - 無効・削除でない問題だけを返す出題対象ビュー（呼び出し側の権限で評価）と、一覧・部分一致・紐づけ・木の探索用の index を作る
  - 完了状態: DB リセットで migration が適用され、正解0個・2個のコミット、他科目への紐づけ、循環する親の設定がそれぞれエラーになる
  - _Boundary: supabase/migrations/20261104000000_catalog_schema.sql_
  - _Requirements: 1.1, 1.2, 1.3, 2.3, 3.4, 4.1, 4.2, 4.3, 5.10, 6.4, 6.5_

- [ ] 1.2 カタログの RPC と部分木関数の migration を作る
  - 自身を含む配下のキーワード ID を重複なく返す部分木関数を作る（存在しない ID は0行）
  - 問題・選択肢・紐づけを1トランザクションで作成・更新し、既存 ID を保ち、外された選択肢に除外日時を付け、表示順の一時衝突を避ける保存 RPC を作る
  - キーワードの移動（移動先の兄弟の末尾）、兄弟集合が一致する場合だけの並べ替え、削除の影響件数の事前集計、部分木の削除と紐づけ喪失時の無効化を行う RPC を作る
  - 科目の論理削除（配下の問題を削除状態、キーワードを削除）、問題の無効化と有効化（紐づけ0件の有効化を拒否）、絞り込み付きの問題検索（新しい順、同時刻は ID 順、語のエスケープ）の RPC を作る
  - すべて呼び出し側の権限で実行し、検索パスを空にしてスキーマ修飾し、認証済みユーザーだけに実行権限を与える
  - 完了状態: ローカル DB で各 RPC を呼び、保存後の ID 不変、移動・並べ替えの結果、削除時の無効化件数が期待どおりになる
