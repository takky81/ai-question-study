# Requirements Document

## Project Description (Input)

所有者は、登録した問題を効率よく繰り返し解き、解答しながら問題の品質フィードバックを残す手段を持たない。現状は問題カタログで科目・キーワード階層・問題を登録できるだけである。所有者がモバイルで科目とキーワードの範囲を選んで出題を開始し、間隔反復（SRS）に基づく順で問題を解き、正誤・解説・キーワード階層を確認し、問題にフラグを付けられるようにする。あわせて、統計機能と取込・出力機能が参照する解答の集計、問題フラグ、定着率を提供する。

## Introduction

本機能は、所有者が出題範囲（科目とキーワードの部分木）を選んで問題を解く「出題セッション」を提供する。出題順は、未出題の問題を先に、次に定着率が低い順とする。解答ごとに履歴を記録し、問題単位の SRS 状態を更新する。正誤判定後は、選択と正誤を1つの選択肢内で同時に示し、問題と各選択肢の解説、紐づくキーワードの階層を表示する。所有者は判定後に問題フラグ（`product.md` の「問題フラグ」）を付けられる。解答画面と開始までの導線はモバイル優先とする。

## Boundary Context

- **In scope**: 出題範囲の選択と開始、SRS による出題順と状態の更新、解答履歴の記録、「わからない」と「？」エリアによる解答、正誤・解説・キーワード階層の表示、出題中の問題の正答数・出題数・正答率の表示、問題フラグの記録と状態（未解消／解消済み）、問題ごと・キーワードごとの集計、定着率の公開、取込で修正された問題のフラグを解消済みにする仕組み
- **Out of scope**: ヒストグラムなど統計の可視化（統計機能）、フラグや集計の出力とフラグを使った問題の修正（取込・出力機能）、問題の作成・編集・無効化・削除（問題カタログ）
- **Adjacent expectations**: 問題カタログが公開する「出題・集計の対象となる問題」の定義とキーワード階層をそのまま使い、無効化・削除された問題は出題・集計の対象にしない。統計機能と取込・出力機能は、本機能の集計・フラグ・定着率を参照するだけで変更しない。フラグの解消は、取込機能が問題を修正するのと同じ一括処理の中でだけ行われ、利用者が直接実行することはできない。正誤の色・選択表示の部品・全件取得・認証は基盤機能のものを使う

## Requirements

### Requirement 1: 出題範囲の選択と開始

**Objective:** 所有者として、スマートフォンで科目とキーワードの範囲を選んですぐに出題を始めたい。それによりすき間時間に目的の範囲だけを解ける。

#### Acceptance Criteria

1. 所有者が出題の導線を開いたとき、出題セッションは所有者の科目一覧を表示する
2. 所有者が科目を選んだとき、出題セッションはその科目のキーワード階層を木として表示し、任意の深さのキーワードを範囲として選べるようにする
3. 所有者がキーワードを範囲として選んだとき、出題セッションは、そのキーワードと配下のすべてのキーワード（途中のノードを含む）のいずれかに紐づく問題を出題対象とする
4. 所有者がキーワードを選ばずに科目だけを選んだとき、出題セッションはその科目の問題すべてを出題対象とする
5. 所有者が範囲を選んだとき、出題セッションは開始前に、範囲内の出題対象の問題数と、そのうち未出題の問題数を表示する
6. 選んだ範囲に出題対象の問題が1問もない場合、出題セッションは開始できないことと理由を表示し、出題を開始しない
7. 所有者が出題を開始したとき、出題セッションは解答画面に移り、最初の問題を表示する
8. 出題セッションは、無効化または削除された問題を出題対象と件数に含めない
9. 出題セッションは、範囲の選択と開始の導線を、モバイル幅で横スクロールなく操作できるようにする

### Requirement 2: SRS による出題順

**Objective:** 所有者として、まだ解いていない問題と身についていない問題から順に出題されたい。それにより限られた時間で効率よく定着させられる。

#### Acceptance Criteria

1. 出題セッションは、範囲内の未出題の問題を、出題済みの問題より先に出題する
2. 未出題の問題がない間、出題セッションは定着率が低い問題から順に出題する
3. 出題セッションは、出題の優先度が同じ問題どうしの順序を、毎回同じ規則で一意に決める
4. 所有者が1問の解答を終えて次へ進んだとき、出題セッションは直前の解答の結果を反映した出題順で次の問題を選ぶ
5. 同じセッション内で範囲のすべての問題を1回ずつ解き終えたとき、出題セッションは終了を表示し、そのセッションの解答数と正答数を示す
6. 出題セッションは、定着率を問題ごとに1つの数値として、統計機能と取込・出力機能から参照できるようにする
7. 出題セッションは、一度も解答していない問題の定着率を「未出題」として値なしで示す

### Requirement 3: 解答と履歴・SRS 状態の記録

**Objective:** 所有者として、解答するたびに結果が確実に記録されたい。それにより出題順と統計が実際の解答に基づく。

#### Acceptance Criteria

1. 所有者が通常の選択領域で選択肢を選んだとき、出題セッションは正誤を判定し、解答履歴（問題、選んだ選択肢、正誤、解答の種類、日時）を記録し、正誤に応じて問題の SRS 状態を更新する
2. 出題セッションは、解答履歴の記録と SRS 状態の更新を一体として行い、一方だけが保存された状態を残さない
3. 解答の記録に失敗した場合、出題セッションは正誤判定の結果を表示したまま、記録に失敗したことと再試行の操作を表示する
4. 所有者が記録の再試行を行ったとき、出題セッションは同じ解答を1回だけ記録する
5. 解答の記録が完了するまでの間、出題セッションは同じ問題への二重の解答と次の問題への移動を受け付けない
6. 出題セッションは、解答履歴と SRS 状態を、それを記録した所有者だけが閲覧・変更できるようにする
7. 問題が後から無効化・削除された場合でも、出題セッションはその問題の解答履歴を削除せずに保持する

### Requirement 4: 「わからない」と「？」エリアによる解答

**Objective:** 所有者として、知らない問題は「わからない」と答え、推測で答えるときはそれを区別して記録したい。それにより定着率が知識による解答だけを反映し、推測で解ける問題を見つけられる。

#### Acceptance Criteria

1. 出題セッションは、問題の選択肢の末尾に、問題データには含まれない固定の「わからない」選択肢を表示する
2. 所有者が「わからない」を選んだとき、出題セッションは誤答として解答履歴に記録し、出題数に数え、SRS 状態を最低の評価で更新する
3. 正誤を判定する前の間、出題セッションは各選択肢の右端に、通常の選択領域とは区別された「？」エリアを表示する
4. 所有者が「？」エリアで選択肢を選んだとき、出題セッションは正誤を判定して解答履歴に記録し、出題数と正答数に数え、その問題に `guessable` フラグを付ける
5. 所有者が「？」エリアで解答したとき、出題セッションはその問題の SRS 状態と定着率を変更しない
6. 出題セッションは、「？」エリアと通常の選択領域を、それぞれ44px 相当以上の操作領域と、境界がわかる見た目で分けて表示する
7. 出題セッションは、「わからない」の選択肢に「？」エリアを表示しない

### Requirement 5: 正誤・解説・キーワードの表示

**Objective:** 所有者として、判定後に自分の選択と正解、解説、学習対象の位置づけを一度に確認したい。それにより間違えた理由をその場で学べる。

#### Acceptance Criteria

1. 正誤を判定したとき、出題セッションは選んだ選択肢に、選択表示と正誤表示を1つの選択肢内で同時に表示する
2. 所有者が正解を選んだとき、出題セッションはその選択肢に選択表示と正解表示を表示する
3. 所有者が不正解の選択肢または「わからない」を選んだとき、出題セッションはその選択肢に選択表示と誤答表示を表示し、正解の選択肢に正解表示を表示する
4. 出題セッションは、正解表示と誤答表示を全画面共通の正誤の色で示し、色以外の印（記号など）を併せて示す
5. 正誤を判定したとき、出題セッションは問題全体の解説を表示し、各選択肢の解説をその選択肢の枠内に表示する
6. 正誤を判定したとき、出題セッションは問題に紐づくキーワードを、科目の根からの階層パスとして表示する
7. 正誤を判定する前の間、出題セッションは正解・解説・紐づくキーワードを表示しない
8. 正誤を判定した後の間、出題セッションはその問題の選択肢を再度選べないようにし、次の問題へ進む操作を表示する
9. 正誤を判定したとき、出題セッションは各選択肢の「？」エリアを表示しなくし、その位置に、正解の選択肢には「○」、所有者が選んだ不正解の選択肢と選んだ「わからない」には「×」を表示し、それ以外の選択肢には記号を表示しない
10. 正誤を判定した後の間、出題セッションは次の問題へ進む操作を、ページのスクロール位置にかかわらず画面の右下に表示し続ける
11. 次の問題へ進む操作を画面の右下に表示している間、出題セッションは、問題・解説・フラグの内容がその操作に隠れて読めなくならないようにし、モバイルの画面下部の導線とも重ならないように表示する

### Requirement 6: 出題中の問題の成績表示

**Objective:** 所有者として、いま解いている問題の過去の成績を見たい。それにより苦手な問題かどうかを解答前後で意識できる。

#### Acceptance Criteria

1. 解答中の間、出題セッションは出題中の問題のこれまでの正答数・出題数・正答率を表示する
2. 正誤を判定したとき、出題セッションは今回の解答を反映した正答数・出題数・正答率をその場で表示する
3. 出題セッションは、出題数が0の問題の正答率を数値ではなく「未出題」と表示する
4. 出題セッションは、成績の出題数と正答数に、通常の解答、「わからない」、「？」エリアによる解答をすべて数える

### Requirement 7: 問題フラグの記録

**Objective:** 所有者として、解答後に問題の品質の問題点を記録したい。それにより問題の修正・作成のヒントを残せる。

#### Acceptance Criteria

1. 正誤を判定したとき、出題セッションは `product.md` の「問題フラグ」のうち `guessable`、`low_value`、`needs_explanation`、`defective` のチェックボックスと、`comment` の自由入力欄を、同じ表示名で表示する
2. 所有者がフラグのチェックボックスを選択したとき、出題セッションは保存の操作を待たずに、問題・フラグの識別子・日時を、未解消の状態で記録する
3. 問題に未解消の同じフラグがすでにある場合、出題セッションはそのチェックボックスを選択済みとして表示し、同じフラグを重複して記録しない
4. 所有者が未解消のフラグのチェックを外したとき、出題セッションは保存の操作を待たずにそのフラグを記録から外し、解消済みの履歴は変更しない
5. 所有者が自由入力欄からフォーカスを外したとき、出題セッションは、入力内容が最後に保存した内容から変わっている場合に限り、空白以外を含む入力内容を `comment` フラグとして未解消の状態で記録する
6. フラグの保存に失敗した場合、出題セッションは入力を保持したまま、失敗したことと再試行の操作を表示する
7. 所有者が「？」エリアで解答したとき、出題セッションは判定後の `guessable` のチェックボックスを選択済みとして表示する
8. 出題セッションは、フラグを、それを記録した所有者だけが閲覧・変更できるようにする
9. 自由入力欄からフォーカスを外したときに入力が空白だけの場合、出題セッションは `comment` フラグを記録せず、未解消の `comment` フラグがあれば記録から外す
10. 出題セッションは、問題フラグ専用の保存ボタンを表示しない

### Requirement 8: フラグの解消

**Objective:** 所有者として、取込で修正した問題のフラグが自動で解消されてほしい。それにより修正済みの指摘が次の修正依頼に残らない。

#### Acceptance Criteria

1. 取込機能が問題を修正したとき、出題セッションはその問題の未解消のフラグを、同じ一括処理の中で解消済みにし、解消した日時を記録する
2. 出題セッションは、解消済みにしたフラグを削除せず履歴として保持する
3. 取込機能の一括処理が失敗した場合、出題セッションはフラグの状態を変更しない
4. 利用者がフラグの解消処理を直接実行しようとした場合、出題セッションはそれを拒否する
5. 出題セッションは、フラグごとに未解消か解消済みかを、取込・出力機能から判別できるようにする

### Requirement 9: 問題ごと・キーワードごとの集計

**Objective:** 統計機能と取込・出力機能の利用者として、問題ごと・キーワードごとの正答数・出題数・正答率を参照したい。それにより弱い問題やキーワードを把握し、修正の対象を選べる。

#### Acceptance Criteria

1. 出題セッションは、出題対象の問題ごとに、正答数・出題数・正答率・定着率・最後に解答した日時を参照できるようにする
2. 出題セッションは、キーワードごとに、そのキーワードと配下のすべてのキーワードのいずれかに紐づく出題対象の問題を範囲として、正答数・出題数・正答率を参照できるようにする
3. 1つの問題が同じ集計範囲の複数のキーワードに紐づく場合、出題セッションはその問題の解答をそのキーワードの集計で1回だけ数える
4. 出題セッションは、無効化または削除された問題を、問題ごと・キーワードごとの集計に含めない
5. 出題セッションは、出題数が0の問題またはキーワードの正答数と出題数を0、正答率を値なしとして示す
6. 出題セッションは、集計を所有者自身の解答だけから算出し、他の利用者に返さない
7. 出題セッションは、問題やキーワードが1,000件を超える場合も、集計の行を欠落・重複なく参照できるようにする

### Requirement 10: 解答画面の操作性

**Objective:** 所有者として、スマートフォンの片手操作で誤タップせずに解答したい。それにより移動中でも快適に学習できる。

#### Acceptance Criteria

1. 出題セッションは、解答画面と範囲選択の画面を、学習区分の導線から開けるようにし、ログインしていない利用者には表示しない
2. 出題セッションは、解答画面をモバイル幅で横スクロールなく表示し、PC 幅でも同じ操作で解答できるようにする
3. 出題セッションは、選択肢、「？」エリア、「わからない」、次へ、フラグの操作を、キーボードで操作でき、フォーカス位置が見えるようにする
4. 出題セッションは、選択状態と正誤状態をライト・ダークの両テーマで判別できるコントラストで表示する
5. 問題の取得に失敗した場合、出題セッションは失敗したことと再試行の操作を表示する
6. 所有者が解答画面から出題を終了したとき、出題セッションは範囲選択の画面に戻り、記録済みの解答を保持する
