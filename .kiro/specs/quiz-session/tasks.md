## Implementation Notes

- 1.1: 3テーブルの FK は on delete restrict のため、解答・SRS・フラグを作る E2E は後片付けでそれらを先に消す必要がある（GUC `quiz.write_via_rpc` を立てる直接 SQL 接続、またはテスト専用の手段）。RPC は `set_config('quiz.write_via_rpc','on', true)`（トランザクション限定）を使い、入力検証なしにこの設定を立てる公開関数を作らない。
- 1.2: srs_next は plpgsql immutable（design.md を更新）。good は更新前の ease を掛ける。
- 1.3: keyword_stats はキーワード1行ごとに keyword_subtree_ids を呼ぶ。1.5 の大量 seed 投入後に全件取得の所要時間を確認すること。
- 1.4: record_answer の既存結果の組み立ては内部関数 quiz_private.existing_answer_result（設計外の補助、authenticated のみ実行可）に置いた。同じ冪等キーの同時実行は2セッションで確認済み（履歴1件、SRS 1回）。
- 1.5: seed の所有者は 11111111-1111-4111-8111-111111111111。科目「E2E 出題テスト」a0000000-0000-4000-8000-000000000001（q1〜q7、正解は position 1）と「E2E 大量データ」b0000000-0000-4000-8000-000000000001（1,050 問・1,200 キーワード）。keyword_stats の全件取得はローカルで約 400ms。
- 2.1: DB の btrim は ASCII 空白のみ除去し、JS の trim は全角空白・改行も除去する。2.5 の api.ts は save_question_flags を呼ぶ前に必ず normalizeComment を適用すること。
- 2.2: DB の timestamptz の JSON は小数秒の桁数が可変で、オフセットも異なり得るため、日時は文字列でなく Date.parse で比べる。
- 2.3: 百分率は Math.round の整数。不正な keyword は範囲全体を null にする（範囲選択へ置換遷移）。UUID 正規表現は QuestionEditPage と重複しており、共通化は別タスクで検討。
- 2.4: session.ts は設計外の nextQuestionId(state) を export（読込中に取得する問題 ID）。answered は読み込んだ選択肢の isCorrect で即時判定し、recordSucceeded で RPC の結果に置き換える。2.5 の API は QuizChoice.isCorrect を必ず渡すこと。
- 3.1: ChoiceList の props は { choices, selection, correctChoiceId, disabled?, onAnswer(kind, choiceId) }。package.json に lint スクリプトはなく、検証コマンドは typecheck / test / build。
- 3.2: AnswerFeedback の props は { judged, explanation, keywordIds, keywords: KeywordNode[] }。QuestionStatsBar は aria-live=polite。
- 3.3: FlagForm は初期値をマウント時だけ読む。4.2 では listOpenFlags の完了後に <FlagForm key={questionId} …/> で描画すること。
- 3.4: KeywordRangePicker は制御型 {keywords, selectedKeywordId, onSelect, label?}（null＝科目全体）。URL の keyword が科目のキーワードにない場合の扱いは 4.1 で決める（範囲なしとして範囲選択に留める等）。字下げは深さで無制限に増える（深さ10で約184px）。
- 4.1: QuizStartPage は URL を初期状態として一度だけ読み、確定した範囲を replace で URL に書き戻す。URL の古い keyword は科目全体にして URL からも外す。解答画面への遷移先は /quiz/play?subject&keyword。
- 4.2: 読込失敗の再試行は、候補未取得なら loadTry で取り直し、取得済みなら candidatesLoaded(state.candidates) で loading に戻す（解答済み・集計は保持）。候補の取り直し中は error 表示が残る（軽微）。
- 4.3: 学習区分に「出題」が加わったため router.test.tsx の 5.6 の間接テストを書き換えた（5.6 は NavLinks.test.tsx と AppLayout.test.tsx で確認）。モバイル下部バーの「出題」は 5.2 の E2E で確認する。
- 5.1: e2e/quiz-db.spec.ts の SQL 接続は docker exec psql（SUPABASE_DB_CONTAINER で変更可、CI では E2E を実行しない）。後片付けは子テーブルだけ session_replication_role=replica で消してから科目を削除する。seed の問題には解答を作らない。
- 5.2: e2e/quiz.spec.ts の後片付けは共通接頭辞 quiz-ui-% で消す（workers: 1 前提）。並列実行にする場合は run 単位に絞ること。
