# Brief: quiz-session

## Problem

登録した問題を効率よく繰り返し解き、解答しながら問題の品質フィードバックを残す手段がない。

## Current State

subject-catalog で問題を登録できるだけである。

## Desired Outcome

ユーザーがモバイルで科目・キーワード範囲を選んで出題を開始できる。SRS に基づく順で問題を解き、正誤・解説・キーワード階層を確認し、問題にフラグを付けられる。

## Approach

解答ごとに履歴を記録し、問題単位の SRS 状態を更新する。出題順は 1. 未出題 2. 定着率（SRS 状態）が低い順とする。解答画面はモバイル優先で実装する。

## Scope

- **In**:
  - 出題範囲（科目・キーワードの部分木。途中ノードに紐づく問題も含む）の選択と、開始までの導線（モバイル優先）
  - 無効化された問題（subject-catalog の定義）は出題せず、集計ビューからも除外する
  - SRS による出題順と SRS 状態の更新、解答履歴の記録。SRS の方式は設計で決めるが、定着率は出題順に使う1つの数値として外部に公開する
  - 選択肢の末尾に固定の「わからない」選択肢。誤答として履歴に記録し、出題回数に数え、SRS は最低評価で更新する
  - 選択肢の右端に「？」エリアを置く。ここをクリックして解答すると `guessable` フラグが自動で付く。正誤は履歴に記録して出題回数・正答数に数えるが、知識による解答ではないので SRS は更新しない
  - 問題ごと・キーワードごと（配下の階層を含む）の正答数・出題数・正答率の集計ビュー。learning-stats と question-exchange が参照する
  - 問題フラグのテーブルと状態（未解消／解消済み）、および取り込みで修正された問題のフラグを解消済みにする SQL 関数（question-exchange の取込 RPC が同じトランザクション内で呼ぶ）
  - 正誤表示：選択表示と正誤表示を 1 つの選択肢内で同時に表示する。正解したときは選択表示＋正解表示、誤答のときは選択表示＋誤答表示に加え、正解の選択肢に正解表示をする
  - 正誤判定後、問題の解説と各選択肢の解説を選択肢の枠内に表示する
  - 正誤判定後、対象のキーワードを階層込みで表示する
  - 出題中の問題の正答数・出題数・正答率を、解答中と正誤判定後の両方で表示し、判定結果をその場で反映する
  - 正誤判定後に表示するフラグ用チェックボックスと自由入力欄（項目は `product.md` の「問題フラグ」）
- **Out**: ヒストグラム統計画面、フラグの出力、問題の無効化・削除（subject-catalog）。

## Boundary Candidates

- 出題順・SRS（純粋ロジック）
- 解答・履歴・SRS 更新の RPC
- 解答画面 UI
- フラグの保存
- 集計ビュー
- フラグ解消の SQL 関数（取込 RPC の内部からだけ呼ぶ）

## Out of Boundary

- 統計の可視化（learning-stats）
- フラグを使った問題の修正（question-exchange）

## Upstream / Downstream

- **Upstream**: subject-catalog
- **Downstream**: learning-stats（集計ビュー）、question-exchange（フラグ・集計ビューの参照、フラグ解消の SQL 関数）

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: subject-catalog

## Constraints

UI は `tech.md` の規約（モバイル優先、操作領域、正誤色）に従う。「？」エリアと通常の選択領域を誤タップしにくくする。解答の記録と SRS の更新は単一トランザクションで行う。
